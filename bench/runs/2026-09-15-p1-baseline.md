## What the table says

- **Joern reproduces the July hand-trace exactly:** bugs 22, 23, 24, 25, plus the documented
  bait on `db.find_product`, and nothing else. This is the exit gate for P1 and it passed.
- **The engines are disjoint.** bandit found {1-8, 14, 15, 16, 20}; semgrep found
  {1-9, 13, 14, 16, 18}; joern found {22-25}. The README's "overlap by exactly zero" claim is
  now a measured fact, not an assertion. Union of all three: 19 of 26.
- **Seven bugs nobody finds:** 10 SSRF, 11 XXE, 12 path traversal, 17 default creds,
  19 cleartext, 21 CORS, 26 the undocumented /login. That is the frontier for the LLM tier.
- **Both bait rows held.** No arm flagged `user_by_name`. Only joern flagged `find_product`,
  by design; whether the LLM clears it is the `full` arm's job and needs a Gemini key.
- **bandit's two FPs are import noise** (`import pickle`, `import subprocess`), not
  mislabelled bugs. semgrep's one apparent FP was CWE-96 on the SSTI line - the same bug as
  the key's CWE-1336; the family map was corrected and semgrep's precision is 1.0.
- **`full` arm not run:** no `GEMINI_API_KEY`, so every verdict would be "Unverified", which the
  policy scores as neither reported nor cleared. Running it now would show recall 0 and prove
  nothing. It is the first run to do once a key is in `.env`.

## Policy decisions made while building the key (need adjudication)

1. Bugs 17, 20, 21 each got a second location in `config.py` where the value is defined
   (VULNERABILITIES.md names both places). A bug is a `key_no`; a bug with two locations found
   at either is one TP. This turned bandit's B104 on `HOST = "0.0.0.0"` from an FP into the
   TP it is.
2. Bug 26 (`/login` discards `verify_login()`'s result) is in the key as `undocumented`. It
   is not in VULNERABILITIES.md. If the team decides it is not a planted bug, delete the row
   and bump the key version.
3. Bug 102 (`find_product`, authz, safe) is locator bait, distinct from bug 101
   (`user_by_name`, injection, safe). Same function as bug 1 (injection, vuln); separate
   family, separate row.
4. CWE-96 was added to the `xss` family alongside CWE-1336 (both SSTI).

## Addendum - the `full` arm, with a Gemini key (same day)

| arm | TP | FN | FP | bait FP | TN | recall | reach. recall | precision | F1 | s |
|---|---|---|---|---|---|---|---|---|---|---|
| full (bandit + joern + RAG + gemini-2.5-flash-lite) | 15 | 11 | 1 | 1 | 1 | 0.58 | 0.47 | 0.88 | 0.70 | 37.9 |

- **Best arm, and it is the union**: bandit's 11 + joern's 4 = 15, all Confirmed by the LLM.
  Recall 0.58 vs 0.46 (bandit alone) and 0.15 (joern alone). This is the hybrid claim, measured.
- **The `find_product` bait was Confirmed, not cleared.** July's design note says the LLM clears it
  ("products are public data"). With `gemini-2.5-flash-lite` and titles-only exemplar grounding it
  did not. The August audit flagged that `_batch_prompt` passes exemplar titles only while the richer
  `_prompt` (bodies) is dead code; this is the first measured consequence. Not fixed in P2 (rules),
  it is a P5/verifier item.
- **The one FP (`cart.py:3`, bandit B403 `import pickle`) is a slice artifact, not an LLM error.**
  `extract_slice` on a module-level line returns a +/-8-line window, which reaches `load_cart()`'s
  `pickle.loads` on line 11. The LLM confirmed the RCE it was actually shown, under the import
  finding's label. Bug 8 is separately and correctly a TP via B301 on line 11. Fix belongs in
  extract.py (module-level findings should get a 0-line or import-only slice), not in the verifier.
- **Gemini availability is a reproducibility hazard.** Three consecutive pipeline runs: (1) 22 x
  `Error` - transient, all retries exhausted; (2) 21 Confirmed + 1 Informational; (3) partial
  `503 UNAVAILABLE "This model is currently experiencing high demand"`. The verdict on any given
  finding can differ run to run for reasons unrelated to the code. O4 must report LLM arms as
  mean-of-N with spread and pin a dated model id, as the August plan already says; this is why.
- Run artifact: `bench/runs/20260915T084600Z-shopfast-full.json` (the run that completed).
