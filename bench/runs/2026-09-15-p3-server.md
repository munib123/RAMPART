# P3 - CPGQL server sidecar, 2026-09-15

Goal: stop paying the JVM start + script compile on every scan, and make one broken rule cost
that rule instead of the whole phase. Mechanism: `joern --server` on 127.0.0.1:8091 (random
per-process Basic-auth password), started by the FastAPI lifespan, one `POST /query-sync` per
`// @@` section of `locators.sc`, `delete(<proj>)` after every scan. Script mode stays as the
fallback whenever the server is off, not up yet, or fails before the rules run.

killing the backend with the same tree-kill. `Popen.terminate()` alone leaves the JVM alive.

## Bugs found on the way (all fixed, all pinned by `backend/tests/test_joern.py` - 20 tests as of the 2026-09-15 review)

1. **`wait_ready(0)` never probed.** `while time.time() < deadline` with `timeout=0` never ran,
   so with the default `JOERN_SERVER_WAIT=0` a fully started sidecar was never marked ready and
   every API scan silently took the script path (`[script]` in the log, no fallback message,
   because it never entered server mode at all). The standalone gate missed it because the bench
   backend calls `wait_ready(120)`. Now probes at least once.
2. **`/query-sync` `success` is HTTP success.** Compile errors and thrown exceptions come back
   `success: true` with the diagnostic in stdout. `evaluation_failed()` parses the Scala 3
   banner (`-- [E006] Not Found Error:` / `-- Error:`), the `N errors found` summary, and
   fully-qualified `...Exception|Error` lines; plain words like `unauthorized` or `Error` inside
   rule text do not trip it.
3. **`importCode` NPE in server mode** - `InstallConfig.rootPath` resolves the install dir from
   its class's CodeSource, which is null for REPL-compiled code. `SHIFTLEFT_OCULAR_INSTALL_DIR`
   is checked first; `runtime.subprocess_env()` sets it to `joern_home` (harmless in script mode).
4. **Health lied about readiness** (`ready: false, startup_s: 41.7` = time since start).
   `status()` now does one cheap probe when running-but-unmarked and reports `uptime_s` and
   `startup_s` separately.

## Operational notes

- Two processes on one machine (backend + bench harness, or two backends) both want 8091. The
  second sidecar fails to bind and dies; `alive()` is false; that process falls back to script
  mode. Graceful, but its timings are script-mode timings - check `joern.mode` before quoting.
- A stale backend process holding :8000 will answer requests with pre-P3 code (`KeyError:
  'server'` / `'mode'`). `netstat -ano | findstr :8000` → `taskkill /T /F /PID`.
- `JOERN_SERVER=off` keeps everything in script mode; `JOERN_SERVER_WAIT=<s>` makes a scan
  wait that long for a starting sidecar before falling back.
- Gemini `503 UNAVAILABLE (high demand)` hit 2 of the 3 API scans (every verdict `Error`); the
  third gave 4 Confirmed + `unchecked-quantity` Informational. Same hazard as P1, not Joern's.
